## Week 1: Project Proposal

### Planned Working Time

I'll be working on this project on Tuesdays and Thursdays from 10am - noon.

### Project Pitch

Towers of Hanoi is a famous puzzle in which the player needs to move a stack of sized discs from one tower to another. In the game, there are three towers. The rules of the game are1:

1. Only one disk can be moved at a time.
2. Each move consists of taking the upper disk from one of the stacks and placing it on top of another stack or on an empty rod.
3. No larger disk may be placed on top of a smaller disk.

In this project, I will create a playable game of Towers of Hanoi. I will include a button to show solving the game, for which students will create functionality in the module on recursion.

![GUI sketch diagram](https://sdccd.instructure.com/courses/2490701/files/153220143/preview)

The GUI will have three buttons with a graphic representation of the current state of the towers on them. The user will click on two buttons, then click the Move button to move a disc between the two selected towers (the program will automatically determine which direction the disc can move); the number of moves label will also increase by 1. If the user wants to see a solution, they can click the "Show Solution" button, and the program will start by resetting the puzzle to its initial state, and then will display each move needed to solve the puzzle, keeping track of the moves as they are made.

### UML Diagram

This is the basic UML for the game. It doesn't have any of the UML for the GUI at first, as I want to write the game classes first, and then will add to the design to create the GUI (likely a Tower will need to learn how to draw itself).

Within the game, the move method is responsible for figuring out which tower has the smaller disc size on top, and then moving that disc from one tower to another (using the removeDisc and addDisc methods), and then also updating the numberOfMoves that have been made. The solve() method will work using recursion, and will be left to students to implement in class during the recursion module.

### Learning Outcomes

- LO1: Employ design principles of object-oriented programming
  - I started with the rules of the game, and created classes based on the nouns in game rules. Then, I used CRC cards to determine what the responsibilities were for each class, and create the game UML based on that. I'm using a model-view-controller (MVC) design for the GUI, which means that I'm creating the model (e.g. the game) first, and then I'll figure out the view-controller part in separate classes.
- LO2: Construct programs utilizing single and multidimensional arrays
  - I'm using an array of 3 towers in the game.
- LO3: Construct programs utilizing object and classes in object-oriented programming, including aggregation
  - TowersOfHanoiGame HAS-A Tower HAS-A Disc.
- LO4: Construct programs utilizing inheritance and polymorphism, including abstract classes and interfaces
  - There is no inheritance in the design yet, but when the GUI is designed, I'll be extending JButton and probably implementing a lot of interfaces to enable event handling!
- LO5: Construct programs using generic collections and data structures
  - I might use ArrayLists instead of arrays for the towers. A stack would work pretty well too.
- LO6: Construct programs utilizing graphical user interfaces utilizing event-driven programming.
  - The user will interact with this code through a GUI.
- LO7: Construct programs utilizing exception handling
  - As I write the program, I will look for places that need exception handling.
- LO8: Construct programs utilizing text file I/O
  - There is no text file I/O in this program. But, if I needed it, I could record the moves made by writing to a file.
